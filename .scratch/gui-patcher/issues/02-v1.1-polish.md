## Notes for v1.1

Raised by the user after the KC 2.5 admission build (ticket 01, stories
16-19, commit `99945af`) was confirmed working as expected.

1. **The GUI shows no version number anywhere.** Neither the exe's file name
   (`dist/ApePatchExtensions.exe`, hardcoded in `src/patcher_gui/build.cmd`)
   nor the window header (`MainForm.cs` `RenderHeader()`, which renders
   `install.InstallPath` / `BuildName` / `HsieVersion` / `Sha256` but nothing
   about APE's own version) says which APE version is running. Needs an APE
   version number surfaced in both places -- useful the moment there is a 1.0
   and a 1.1 both circulating among testers, since a bug report is otherwise
   unattributable to a build.

2. **Hull repair's default range is h.sie's own 5-20%, not APE's.** `PatchState.cs`
   ships `HullMin = 5, HullMax = 20` -- which is deliberately *not a change*
   from h.sie's stock roll (`Test_HullRepairAtHsiesOwnRangeIsNotAChange` in
   `tests/patcher_gui/PatchSessionTests.cs` asserts exactly this: ticking the
   box at the default writes nothing). The user wants APE's actual default to
   be **0-5%**, a real narrowing of h.sie's roll. This changes the meaning of
   "default": the box being ticked at defaults would then be a genuine write,
   not a no-op, and that no-op test will need to change with it.
