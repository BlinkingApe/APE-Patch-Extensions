# APE Patch Extensions — the GUI patcher

One exe, dropped in the SH3 game root. It finds the install by its own location,
shows what is currently applied, lets the player edit hull repair and diesel
damage, and commits every change in one verified write. Unchecking a feature and
applying restores the original bytes exactly — that is the uninstaller.

Spec: [`.scratch/gui-patcher/PRD.md`](../../.scratch/gui-patcher/PRD.md).

## Build and run

```
src\patcher_gui\build.cmd            -> dist\ApePatchExtensions.exe
src\patcher_gui\build.cmd run        build and launch against the live install
tests\patcher_gui\run.cmd            the test suite, swept over two cultures
tests\patcher_gui\run.cmd Session    one class or case
```

`build.cmd` regenerates the patch manifest and fails on drift before it compiles
anything (umbrella ticket 08's stale-manifest guard), then rebuilds the icon from
the portrait art.

A headless check of the window itself:

```
dist\ApePatchExtensions.exe --self-test "C:\games\OneAlex Extended 1.5.2"
```

Builds, lays out and paints the window without showing it. Exit `0` built and the
install was readable, `2` built but the install was refused, `1` it threw.

## Shape

```
PatchState    the desired-state model -- the two features' fields and every
              statistic derived from them. No I/O, no WinForms.
Review        "what will change", in game terms. Never names a file, an
              address or a ValN key.
PatchSession  the only seam. Open reports what an install is and holds; Apply
              verifies every site and writes all of it or none of it.
IniFile       surgical hsie.ini editing -- named keys only, everything else
              byte-preserved.
Manifest      umbrella ticket 08's schema, generated by
              tools/re-static/gen_manifest.py and embedded as a resource.
ui/           WinForms. Holds no logic: it binds controls to a PatchState,
              calls Apply, and renders the reports.
```

Everything worth testing sits behind `PatchSession`, so the suite opens prepared
game directories and asserts on the bytes and the ini text that came out. It
never reaches for a private method and never asserts on control positions.

## Two things to know before changing it

**There is no sh3.exe build check (ticket 13).** APE reads and displays
whatever h.sie version stamp it finds, but never matches it against a list --
h.sie's own installer already refused to run against an sh3.exe it does not
support, so APE inherits that gate rather than duplicating it. Every site's
offset is a single value proven once, not one per admitted build. The
remaining safety net is `Verify()`'s per-site invariant-context-byte check,
which runs before every write and refuses the whole commit if a site's bytes
do not match what APE was proven against.

**Culture invariance is a correctness requirement, not a preference.**
`hsie.ini` is parsed by h.sie's own code, which expects `4.1667e-08`. A
comma-decimal machine writing `4,1667e-08` renders the mod inert with no error
and no in-game symptom. The UI thread is pinned to the invariant culture at
startup and every format and parse goes through `Fmt`; the whole test suite runs
a second time under `de-DE` and must produce byte-identical output.
